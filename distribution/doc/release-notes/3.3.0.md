# Version 3.3.0

Hardware tokens get easier. Several PKCS#11 tokens can be configured side by side and picked by name, a wrong driver no longer breaks startup, and JSignPdf can find installed token drivers for you. Visible signatures now render Chinese, Japanese and Tamil text.

- **Several PKCS#11 tokens at once** — every file in `<config-dir>/pkcs11/` is a named profile next to the existing `pkcs11.cfg` (read as the profile `default`). The GUI lists one `PKCS11 — <label>` entry per profile; the command line selects one with `--keystore-provider` / `-kspr` and lists them with `--list-keystore-providers` / `-lkp`. Keys are now loaded and signed with the selected token even when several offer the same keystore type. See issue 187.
- **Drivers load on first use** — a missing, broken or wrong-architecture driver no longer delays or prevents startup. The **Load Keys** button reports success or the cause of a failure (missing library, wrong PIN, no token) in the window and can simply be pressed again after the problem is fixed. See issue 491.
- **Token detection and a driver catalog** — the PKCS#11 tab of Preferences, now called **Hardware tokens (PKCS#11)**, is a profile table with the label, id, driver and status of each token, a library file chooser, **Detect tokens** and **Add from catalog**. A new profile takes its id from its label, and the raw configuration moved under **Advanced**. The bundled catalog covers OpenSC, the p11-kit proxy, YubiKey PIV, Belgian eID and SafeNet eToken; nothing is applied without confirmation, and JSignPdf never ships drivers. Not available in the Flatpak build, where host drivers cannot be loaded.
- **Clearer PKCS#11 keystore entries** — a profile registers only the SunPKCS11 provider by default instead of both `PKCS11` and `JSIGNPKCS11`; add `#jsignpdf:provider=jsign` or `both` to a profile to get the JSignPdf provider. An existing `pkcs11.cfg` that was used with `JSIGNPKCS11` keeps working, and the keystore file field is hidden for PKCS#11 entries.
- **JSIGNPKCS11 works on Java 21** — signing failed with `IllegalAccessError` or `NoSuchMethodError` for ECDSA keys and for smart cards that only compute raw RSA signatures (for example I.CA cards). The provider is now jsign-pkcs11 1.2.0, based on the OpenJDK 21 PKCS#11 code, and the launchers pass a single `--add-exports` option instead of five JDK-internal flags.
- **Visible signature text in Chinese, Japanese and Tamil** — the bundled DejaVuSans has no glyphs for these scripts, so the DSS engine failed and the OpenPDF engine silently left the characters out of the translated default text or a signer name. JSignPdf now falls back to the bundled Noto Sans SC or Noto Sans Tamil font, and refuses to sign when no font covers the text (for example Korean) instead of dropping characters. The DSS engine embeds only the used glyphs, so a visible signature no longer carries the whole font. See issue 537.
- **Larger downloads** — the bundled Noto Sans SC font adds about 6 MB to every ZIP and installer.
