# Version 3.3.0

Hardware tokens get easier. Several PKCS#11 tokens can be configured side by side and picked by name, a wrong driver no longer breaks startup, and JSignPdf can find installed token drivers for you.

- **Several PKCS#11 tokens at once** — every file in `<config-dir>/pkcs11/` is a named profile next to the existing `pkcs11.cfg` (read as the profile `default`). The GUI lists one `PKCS11 — <label>` entry per profile; the command line selects one with `--keystore-provider` / `-kspr` and lists them with `--list-keystore-providers` / `-lkp`. Keys are now loaded and signed with the selected token even when several offer the same keystore type. See issue 187.
- **Drivers load on first use** — a missing, broken or wrong-architecture driver no longer delays or prevents startup; the profile is shown greyed out with the reason, and _Load Keys_ reports success or the cause of a failure (wrong PIN, no token) in the window. See issue 491.
- **Token detection and a driver catalog** — _Preferences > PKCS#11_ is now a profile list with a library file chooser, _Detect tokens_ and _Add from catalog_. The bundled catalog covers OpenSC, the p11-kit proxy, YubiKey PIV, Belgian eID and SafeNet eToken; nothing is applied without confirmation, and JSignPdf never ships drivers. Inside Flatpak the p11-kit proxy is offered to reach host tokens.
- **Clearer PKCS#11 keystore entries** — a profile registers only the SunPKCS11 provider by default instead of both `PKCS11` and `JSIGNPKCS11`; add `#jsignpdf:provider=jsign` or `both` to a profile to get the JSignPdf provider. An existing `pkcs11.cfg` that was used with `JSIGNPKCS11` keeps working, and the keystore file field is hidden for PKCS#11 entries.
